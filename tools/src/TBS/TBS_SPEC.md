## 1. 형식 4종과 JSON 스키마
파일: `원천/REG/tbs_reg.json` = `{meta, items[]}`. 문항 1개가 TBS 1개. 화면용 정답 없는 사본은 `tbs_문제지_검산용.json`.

### 1-1. 공통 필드(TBS)
| 필드 | 설명 |
|---|---|
| `id` | `REG-{Area}-T-{nnn}` (Area 내 순번) |
| `type` | `"tbs"` |
| `area` | `I`~`V` |
| `format` | `numeric_table` 숫자 입력 표 / `document_review` 문서 검토 / `research` 조사(인용 입력) / `dropdown_judgment` 드롭다운 판단 |
| `title`, `scenario`, `task` | 제목, 사실관계, 지시문(영어) |
| `exhibits[]` | 전시물 목록. `{id, title, kind, body}`. `kind`: `email`(이메일), `memo`, `return_excerpt`(세금신고서 발췌), `contract`, `table`(`body`=행 배열 `[[열...],...]`), `notes`, `statute_note`(법령 발췌) |
| `cells[]` | 답 칸(아래) |
| `params`, `vary`, `guards`, `derived`, `template` | 변형 생성용(1-3) |
| `blueprint` | `{area, group, topic, task, skill}` — 지도.json task 와 같은 틀 |
| `difficulty` | 1~3 |
| `est_minutes` | 권장 풀이 시간(10~16분, 실제 18분 평균보다 짧게 잡아 칸 6~8개 기준) |
| `testable_from` | 이 날짜 이후 시험에 나올 수 있는 법(OBBBA 2024·2025 시행분은 2026-07-01) |
| `law_asof`, `law_note`, `cite[]` | 법령 기준일, 주의, TBS 전체 근거 |
| `status`, `verify`, `provenance`, `version` | MCQ 와 같은 관리 필드. 초기 `draft`; 독립 풀이 통과 후 `verified` |

### 1-2. 칸(cell)
공통: `id`(c1…), `kind`, `label`, `why`(칸별 해설), `steps[]`(풀이 단계), `hints[]`(단계별 힌트), `cite`(칸 근거), `link`(원문 링크), `points`(기본 1).

| kind | 추가 필드 | 채점 |
|---|---|---|
| `number` | `expr`(정답 계산식), `answer`, `tol`(허용오차 0 또는 1), `fmt`, `deps`(앞선 칸 id), `ecf`(bool), `traps[]` = `{expr, value, msg}` | 정답±`tol` = 1점. 아니면 **앞칸 오류 이월(ECF)**: 학생이 입력한 앞칸 값으로 `expr` 을 다시 계산해 일치하면 `ecf_credit`(기본 0.5) |
| `dropdown` | `options[]`(고정 셔플), `answer`(보기 문자열), `wrong_msgs{보기: 왜 틀렸나}` | 일치 1 |
| `citation` | `ask`, `accept[]`(정규형), `partial[]`(0.5점), `link` | 입력을 `norm_cite()` 로 정규화(§, IRC, Sec., 26 USC, 31 CFR, 공백 제거, 소문자)해 `accept`(1점)·`partial`(0.5점) 대조 |

`traps` 는 흔한 실수 값이다. 학생 입력이 `traps[i].value` 와 같으면 정답 대신 `msg`("13% 대신 12% 를 쓰셨네요…")를 보여준다.

### 1-3. 변형 자동 생성(계산식 보관)
- `params`: 기본 숫자. `vary`: `{파라미터: [후보값]}`. `derived`: 파생값 `[[이름, 식]]`(식은 `rnd`, `min`, `max`, `tax_s`, `se_tax`, `dual_basis`, `ltcg_tax` 만 허용, 내장함수 차단). `guards`: 시나리오가 성립하기 위한 조건식 목록.
- `template`: 자리표시자(`{name}`, `{name:,}`)가 들어간 원문. `variant(raw, seed)` 가 후보값을 뽑아 `guards` 를 통과할 때까지 재추출하고, 발문·전시물·해설·정답·오답 진단값을 전부 다시 채운다. 드롭다운 보기 순서도 새 시드로 다시 섞는다.
- 드롭다운·인용 칸의 정답은 숫자에 따라 변하지 않게 만들었고(`guards` 로 보장), 숫자 칸만 새로 계산된다.
- 24개 x 200 시드 = 4,800개 변형이 모두 생성·만점 채점을 통과했다(`tbs_계산검산.py`).

## 2. 베커를 넘는 학습 기능(제안)
공개 자료 기준 베커 TBS 는 "문항 + 해설 + 영상 풀이" 중심이다. 아래는 이 제품이 가능하게 만든 데이터 구조로 바로 구현되는 기능이다.

| # | 기능 | 데이터·방식 | 베커 대비 |
|---|---|---|---|
| 1 | **칸별 부분 점수와 즉시 해설** | 칸마다 `why`·`steps`. 제출 전 "칸 검사" 버튼으로 그 칸만 채점 | 칸별 즉시 확인·해설(공개 자료에서 확인되지 않는 칸 단위 피드백) |
| 2 | **앞칸 오류 이월(ECF) 채점** | `expr` 을 학생 입력으로 재계산. "앞 칸 값이 틀렸지만 이어지는 계산은 맞음: 0.5점" 표시 | 연쇄 실수를 원인 칸에만 물음 |
| 3 | **오답 원인 진단** | `traps`(계산 실수 값)·`wrong_msgs`(보기별 오답 이유) | 정답 공개보다 "왜 그 값이 나왔는지" |
| 4 | **틀린 칸만 다시 풀기** | 채점 후 정답 칸은 잠그고 오답 칸만 열어 재제출(2회차 점수는 0.5배로 별도 기록) | 시나리오 전체 재풀이 없이 |
| 5 | **힌트 한 단계씩** | `hints[0]`(개념) → `hints[1]`(식·기준) → `steps`(정답 풀이). 힌트를 쓸수록 칸 점수 감점 없이 "힌트 사용" 기록만 남김 | 영상 15분 대신 10초 단위 |
| 6 | **IRC 조문 원문 링크** | 인용 칸 `link`(law.cornell.edu). 채점 후 그 조문·소절을 새 탭으로 연다. 조사(research) 형식은 인용 정답 입력 후 조문 원문을 바로 확인 | 근거를 클릭 한 번으로 |
| 7 | **풀이 시간 기록** | TBS·칸 진입/제출 시각 → `est_minutes` 대비 표시. 18분 평균(시험 시간 배분)과 비교 | 시간 관리 훈련 |
| 8 | **숫자 변형 무한 반복** | `variant(seed)` 로 같은 논리의 새 숫자. 틀린 유형은 24시간 뒤 변형으로 재출제(복습박스 연동) | 외워서 맞히기 방지 |
| 9 | **법령 시점 표시** | `testable_from`, `law_note`. 아직 시험에 나오지 않는 개정 법령(OBBBA 2026-07-01 전)은 "연습 전용" 배지 | 최신법 혼동 방지 |
| 10 | **복사 허용 해설** | 해설·풀이는 선택·복사 가능(학습노트용). 베커 후기의 "복사 잠금" 불만 해소 | 후기 불만 반영 |
| 11 | **문서 검토 미리보기** | 문서 검토 형식에서 "원문 vs 수정본" 비교를 채점 후 표시 | 무엇이 바뀌었는지 시각화 |
| 12 | **Area·스킬별 TBS 정답률** | 칸 단위 결과를 `blueprint` 로 집계, 스킬 트리(`skilltree.html`)에 %로 표시 | 칸 단위라 약점이 더 촘촘 |

- 난이도 방침: 베커의 "실제보다 어렵게" 는 따르지 않는다. 난이도 1~3 은 실제 시험 수준(정답률 60~80% 목표)으로 두고, 어렵게 느끼는 유형은 힌트·변형으로 보충한다.

## 3. 화면 구성안
### 데스크톱(가로 1024px 이상): 분할 화면
```
+-----------------------------------------------------------+
| REG · Area IV · TBS 3 of 8   [남은 시간 14:20]   [Flag] [검토] |
+---------------------------+-------------------------------+
| 전시물 탭                   | 과제(지시문 + 칸)               |
| [Exhibit 1][Exhibit 2]... | 1. Total income   [ 79,650 ]   |
| 표·이메일·서식 발췌 (스크롤)   |    [칸 검사][힌트][해설]          |
| 법령 발췌 탭(있는 경우)        | 2. AGI            [ ______ ]   |
|                           | 3. Filing status  [▼ 선택 ]    |
+---------------------------+-------------------------------+
| [이전 TBS]     칸 진행 4/7         [제출]  [틀린 칸만 다시]       |
+-----------------------------------------------------------+
```
- 왼쪽: 전시물 탭(`exhibits[]` 순서). 표는 행 강조, 이메일은 헤더 고정. 탭에 읽음 표시.
- 오른쪽: 지시문 고정, 칸 목록 스크롤. 숫자 칸은 쉼표 자동 입력, 음수는 `-`. 드롭다운은 `options`. 인용 칸은 텍스트 입력 + 형식 안내(`ask`).
- 칸 검사 후 아래에 `why`·`steps`·`traps` 진단·원문 링크 펼침.
### 모바일(폭 768px 미만)
- 상단 탭 3개: **Exhibits | Task | Result**. 전시물 탭 안에서 전시물 서브탭. 칸 입력은 Task 탭에서 카드 1개씩(다음/이전 스와이프), 화면 하단에 "전시물 다시 보기" 고정 버튼(탭 전환 시 입력값 보존).
- 큰 표는 가로 스크롤 대신 행 접기(첫 열 고정).

## 5. 작성 규칙(TBS)
1. 영어 발문, 한국어 관리. 사례형(인물·연도·금액), 조문번호는 발문에 쓰지 않는다(조사 형식만 예외로 인용 입력을 묻는다).
2. TBS 당 칸 5~8개(공식 TBS 도 여러 질문). 숫자는 전부 `expr` 로 계산식을 코드로 남기고 `tbs_계산검산.py` 로 손계산표와 대조.
3. 세율표·한도 등 2026 수치는 전시물·발문에 "가정치"로 준다. 법정 수치를 외우게 하는 칸은 없다(테스트 목적이 다를 때만).
4. 개정법(P.L. 119-21)은 `testable_from` 2026-07-01 과 `law_note` 를 단다.
5. 드롭다운은 3지(문서 검토)~7지(회수기간). 정답이 "Keep as written"인 칸이 전체 1/3 정도 나오도록 섞는다(무조건 고치는 습관 방지).
6. 오답 보기마다 `wrong_msgs` 필수(MCQ 선지별 해설 규칙과 같음). 인용 칸은 `accept` 정규형·`link` 필수.
7. 독립 검산: `tbs_문제지_검산용.json`(정답·해설 제거)을 다른 창에서 풀어 대조 후 `status` 를 `verified` 로.

## 6. 남은 일
- AICPA 공개 샘플 테스트(aicpa-cima.com) 화면 실제 열람으로 형식·입력 방식 대조(이번에는 검색 요약만 사용).
- 독립 풀이 검산 24개.
- TBS 를 REG 시험 구성(8개)에 맞춰 최소 3배(약 72개)로 확대. Area 별 목표: I 12·II 12·III 12·IV 18·V 18.
- 조사 형식: 조문 원문 뷰어(내장 발췌)와 인용 자동 완성 추가.
